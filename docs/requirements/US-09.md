# US-09 Handle recipe service failures

As a user, I want a clear message When recipe generation fails so that I can retry without losing my data.

**Priority:** Must have. **Proposed implementation owner:** Ayşe Döne.

## Acceptance criteria

1. Given a provider timeout or service error, When I request recipes, Then the system displays a retryable error and does not store partial results.
2. Given existing inventory, preferences, shopping items, favorites and history, When recipe generation fails, Then all five collections remain unchanged.
3. Given invalid provider output, When the system processes the result, Then it reports a generation error without exposing provider credentials or raw diagnostics.

## Explicit discovery extension: completed groups during a transport outage

A complementary search may succeed with fewer completed groups while still
returning only whole, validated recipes. In this successful case an explicit
HTTP completion flag and browser notice identify the incomplete search; the
validated result set is committed atomically. It is not reported as a failed
request or a partial recipe. Total unavailability still returns retryable 503
with no writes; a completed malformed/allergen-conflicting response still
rejects the entire result before saving. This deliberate extension is specified
and tested in [recipe generation resilience](../tests/recipe-generation-resilience.md).
